# Remote MCP inventory (2026-11-17)

The application uses Next.js 16 App Router, React 19, TypeScript, Zod, and a build-selected Supabase or CloudBase backend. PostgreSQL business RPCs are the shared service layer: they enforce membership, validation, optimistic versions, operation receipts, and publication updates. `getAuthProvider`, `getRelationalDatabase`, and `getPrivilegedRelationalDatabase` preserve regional isolation. Never edit frozen baseline sources; add provider-neutral migrations under `database/shared/migrations` and regenerate both regional chains.

Existing sign-in supports Supabase sessions (including upstream Google OAuth) and CloudBase sessions. Neither composition implements an authorization server for third-party MCP clients. Supabase now documents an OAuth server, but it is not configured here, and would not cover CloudBase. The implementation therefore uses `@node-oauth/oauth2-server` in the existing Next backend, authorization code with mandatory S256 PKCE, public clients, rotating refresh tokens, exact resource binding, and database-backed grant revocation. Discovery follows RFC 8414/9728. Pre-registration and bounded RFC 7591 public registration are supported; CIMD is deliberately not advertised (no arbitrary server-side metadata fetching).

Existing Research/Idea rows are trip-bound and intertwined with comparisons. Add an independent personal `saved_ideas` library and an itinerary reference; retain trip Research unchanged. A library idea can be referenced by multiple trips; itinerary snapshots and idea revisions remain independent. Add private OAuth clients, connections, hashed credentials, request receipts, previews, audit/undo records, and rate buckets. Browser and MCP use the same new domain service; Trip and item operations call existing RPCs.

Milestones: (1) inventory, (2) database/domain services and isolation tests, (3) OAuth/MCP routes and protocol tests, (4) connection/library/copy-task UI, (5) documentation and regional/deployment verification, (6) real client acceptance, PR, merge after all required gates pass.

Available locally: Node 24, Docker/PostgreSQL 17, GitHub CLI authenticated as repository owner. Existing regional CI has exact-SHA Global/CN jobs and mandatory cleanup/residue audits. External prerequisites: controlled regional credentials and migrations, public HTTPS origin with no deployment login barrier on MCP/OAuth discovery, browser login, and client accounts with remote MCP enabled.
