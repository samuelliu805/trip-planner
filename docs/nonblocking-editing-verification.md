## Implemented behavior

Forms persist raw fields synchronously, including unfinished prices, links and IME input. Existing valid items, Ideas, settings and Plan metadata autosave; new entities require an explicit creation intent. Ordinary close retains fields and accepted work. Desktop editors leave the workspace interactive. Mobile editors keep draft recovery and scoped status. Place resolution owners retain confirmed results after their view closes, apply only to the captured unchanged input, and never automatically repeat an interrupted paid request.

Account-owned outboxes capture immutable operation IDs, dependencies and confirmed baselines. Same-day edits serialize; independent days can progress. ACKs reconcile with pending operations instead of restoring whole snapshots. Known ACKs are persisted before compaction. A response lost after commit replays the same frozen request. Failed, offline and conflicted work remains visible and recoverable. Cross-tab conflicts preserve separate recovery copies; account and region changes isolate owners.

Day/copy/Plan identities are captured before send. Upload owners persist actual File bytes in IndexedDB and continue after the view closes; binding waits for its entity receipt. Attachment collection counters and day item positions reconcile independently from text versions. Item update projections apply the RPC’s full-day canonical numbering; older collection reads cannot restore stale positions while newer row text still merges. Route configuration and paid computation have separate snapshots; interrupted computations require explicit retry. Publishing and image jobs use stable receipts and expose actual URLs only after confirmation. Guest storage remains compatible, and claim continuation uses an exact revision cutoff.
